# 「任务」面板：这个界面想表达什么

这份文档回答一个问题：**「任务」页签为什么要长成这样。** 它写给读界面的人，也写给以后改这个界面的人——信息层级先有理由，才有布局。

## 一、面板要支持的判断

读者只有一个问题：**我现在该等，还是该管？**

| 观察 | 结论 |
| --- | --- |
| 有工具在跑、时间在走 | **等**。它在干活。 |
| 很久没有新动作，但回合没结束 | **看**。可能卡住了，去看「最近动静」和「动作日志」。 |
| 出现失败行 | **管**。看失败码和返回首行，决定重试还是改做法。 |
| 「运行状况」显示数据不再更新 | **不信这份面板**。它可能只是没收到数据。 |

前两行是绝大多数使用场景：**扫一眼就走**。因此面板的顺序是「先结论、再证据、最后自检」——而不是把字段按来源罗列。

## 二、布局规格（横轴=轮次，下面是每轮的插件明细）

```
┌ 顶部：状态 · 正在用的工具 · 已运行 ────────────────────────────┐
├ 汇总一行：N 轮 · M 次调用 · 失败 K · 可用工具 T（用到 D 种）──┤
├ 轮次横轴：[ 第1轮 █████████ ][ 第2轮 ███ ][ 第3轮 █ ] ────────┤   ← 宽度=该轮耗时，时间向右
├ 轮次明细 ────────────────────────────────────────────────────┤
│  第 2 轮   11:58:53  3 秒  1 个工具                          │
│    11:58:56 ● bash   echo second-turn      完成 0 秒  ▾     │   ← 点击展开
│             参数  echo second-turn                           │
│             结果  second-turn                                │
│  第 1 轮   11:58:07  8 秒  3 个工具                          │
│    11:58:14 ● read   /etc/hosts            完成 0 秒  ▾     │
│    11:58:15 ● check_ui_size  #pill @ http… 完成 1 秒  ▾     │
└ 运行状况：面板自检计数 ──────────────────────────────────────┘
```

| 区域 | 回答的问题 | 内容 |
| --- | --- | --- |
| 顶部 | 现在什么状况、用哪个工具 | 状态点 + 阶段 + 工具名 + 已运行 |
| 汇总一行 | 规模多大 | 轮数 / 调用数 / 失败数 / 可用工具与用到几种 |
| 轮次横轴 | 时间花在哪一轮 | 每轮一段，宽度按该轮耗时；点选该轮；失败角标 |
| 轮次明细 | 这一轮触发了哪些插件 | ①每轮一段：起始时间、时长、工具数、失败数 ②每行：时间 + 工具名 + 参数 + 状态与耗时 ③**点击展开参数与结果** |
| 运行状况 | 这份面板还可不可信 | 折叠/忽略/未知类型/流式帧/接管 agent/增量/数据新鲜度 |

**为什么横轴按轮次而不是按时钟**：读者想的是"第 3 轮发生了什么"，而轮与轮之间的长时间空闲会把时钟轴拉得毫无信息。

## 三、信息层级的三条规则

1. **先结论后证据**：顶部一行给状态，模块按其重要性排列，明细在最后。
2. **机器词不进门**：`tool/call`、`step/start`、`session-log-*` 这些是会话日志的词汇，不是读者的；面板只出现人话（工具名与事件名是协议标识符，故意保留原样，因为改写会掩盖"到底是哪个工具"）。
3. **数字必须可核**：每一行都能在会话日志里找到出处；面板不做推测，读不出来就报缺失（`—`），不猜。

## 四、刻意不做的事

| 不做 | 理由 |
| --- | --- |
| 流式文本进度条 | 它来自进程内瞬时帧，落不了日志；显示一个恒为 0 的进度条比不显示更糟 |
| 工具返回全文 | 面板是索引不是阅读器；全文在对话记录里 |
| 完整历史 / 审计 | 动作日志是最近 8 次的窗口，不是账本 |
| 写操作（取消、重试） | 只读面板不会误伤；要动手去对话里做 |
| 常驻右侧栏（v1） | 页签已集成并验证；再加一个面板是新的集成面，换来的能力重复 |

## 五、与参考插件的异同

同一套插槽（`conversation.view`）与同一套原语（`StateDot` / `Tag` / `Pill`），因此视觉语言一致。差别在**信息密度**：参考插件（上下文洞察）面向"分析一个会话的构成"，需要图表与树；本面板面向"此刻该不该管"，因此用卡片 + 表格 + 一行结论，宁可留白也不堆数字。
