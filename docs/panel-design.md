# 「任务」面板：这个界面想表达什么

这份文档回答一个问题：**「任务」页签为什么要长成这样。** 它写给读界面的人，也写给以后改这个界面的人——信息层级先有理由，才有布局。

## 一、面板要支持的判断

读者只有一个问题：**我现在该等，还是该管？**

| 观察 | 结论 |
| --- | --- |
| 有工具在跑、时间在走 | **等**。它在干活。 |
| 很久没有新动作，但回合没结束 | **看**。可能卡住了，去看「最近动静」和「动作日志」。 |
| 出现失败行 | **管**。看失败码和返回首行，决定重试还是改做法。 |
| 「运行状况」显示数据不再更新 | **不信这份面板**。它可能只是没收到数据。 |

前两行是绝大多数使用场景：**扫一眼就走**。因此面板的顺序是「先结论、再证据、最后自检」——而不是把字段按来源罗列。

## 二、布局规格（横轴=轮次，下面是每轮的插件明细）

```
┌ 顶部：状态 · 正在用的工具 · 已运行 ────────────────────────────┐
├ 汇总一行：N 轮 · M 次调用 · 失败 K · 可用工具 T（用到 D 种）──┤
├ 轮次横轴：[ 第1轮 █████████ ][ 第2轮 ███ ][ 第3轮 █ ] ────────┤   ← 宽度=该轮耗时，时间向右
├ 轮次明细 ────────────────────────────────────────────────────┤
│  第 2 轮   11:58:53  3 秒  1 个工具                          │
│    11:58:56 ● bash   echo second-turn      完成 0 秒  ▾     │   ← 点击展开
│             参数  echo second-turn                           │
│             结果  second-turn                                │
│  第 1 轮   11:58:07  8 秒  3 个工具                          │
│    11:58:14 ● read   /etc/hosts            完成 0 秒  ▾     │
│    11:58:15 ● check_ui_size  #pill @ http… 完成 1 秒  ▾     │
└ 运行状况：面板自检计数 ──────────────────────────────────────┘
```

| 区域 | 回答的问题 | 内容 |
| --- | --- | --- |
| 顶部 | 现在什么状况、用哪个工具 | 状态点 + 阶段 + 工具名 + 已运行 |
| 汇总一行 | 规模多大 | 轮数 / 调用数 / 失败数 / 可用工具与用到几种 |
| 轮次横轴 | 时间花在哪一轮 | 每轮一段，宽度按该轮耗时；点选该轮；失败角标 |
| 轮次明细 | 这一轮触发了哪些插件 | ①每轮一段：起始时间、时长、工具数、失败数 ②每行：时间 + 工具名 + 参数 + 状态与耗时 ③**点击展开参数与结果** |
| 运行状况 | 这份面板还可不可信 | 折叠/忽略/未知类型/流式帧/接管 agent/增量/数据新鲜度 |

**为什么横轴按轮次而不是按时钟**：读者想的是"第 3 轮发生了什么"，而轮与轮之间的长时间空闲会把时钟轴拉得毫无信息。

## 三、信息层级的三条规则

1. **先结论后证据**：顶部一行给状态，模块按其重要性排列，明细在最后。
2. **机器词不进门**：`tool/call`、`step/start`、`session-log-*` 这些是会话日志的词汇，不是读者的；面板只出现人话（工具名与事件名是协议标识符，故意保留原样，因为改写会掩盖"到底是哪个工具"）。
3. **数字必须可核**：每一行都能在会话日志里找到出处；面板不做推测，读不出来就报缺失（`—`），不猜。

## 四、刻意不做的事

| 不做 | 理由 |
| --- | --- |
| 流式文本进度条 | 它来自进程内瞬时帧，落不了日志；显示一个恒为 0 的进度条比不显示更糟 |
| 工具返回全文 | 面板是索引不是阅读器；全文在对话记录里 |
| 完整历史 / 审计 | 动作日志是最近 8 次的窗口，不是账本 |
| 写操作（取消、重试） | 只读面板不会误伤；要动手去对话里做 |
| 常驻右侧栏（v1） | 页签已集成并验证；再加一个面板是新的集成面，换来的能力重复 |

## 五、与参考插件的异同

同一套插槽（`conversation.view`）与同一套原语（`StateDot` / `Tag` / `Pill`），因此视觉语言一致。差别在**信息密度**：参考插件（上下文洞察）面向"分析一个会话的构成"，需要图表与树；本面板面向"此刻该不该管"，因此用卡片 + 表格 + 一行结论，宁可留白也不堆数字。

## 七、两个子页签与"插件运行状况"仪表（2026-09-23，PR #52–#54）

活动页顶部两个子页签（真 `role="tab"`，13px 对齐官方页签）：

- **插件活动**（默认）：时间线、横轴、工具栏、抽屉——活动本体原样。
- **插件运行状况**：原先压在时间线底部的遥测整块搬进来，按官方上下文页的结构做**简单表示**（只用本面板可得的数据，不与 `dsh-context` 重复造图）：
  1. **统计卡一排**：轮次 / 调用 / 失败 / 可用工具 / 用到种数；
  2. **Token 用量构成条**：缓存(绿) 输入(蓝) 思考(紫) 输出(橙) 四段 + 图例 + 明细行；
  3. **工具清单**：见 §八的排序统计行；
  4. **诊断组**：已折叠 / 已忽略 / 未知 / 流式帧 / agent·注册表 / 接受·丢弃 / 数据新旧，全量常驻（这个页签就是看它们的地方）。

两个面板共用 `useLiveTaskDisplay`（projection + 客户端档案折叠 + 分页旗标），**同一套数字，不会漂**。

## 八、排序的工具统计行（2026-09-23，PR #55，调用方给定样例）

样例：`check_file_hash  soia 校验文件插件  调用100次 成功100次 失败0次`

- **数据**：fold 新增 `toolStats`——`tool/call` 计次、`tool/result` 计败；state + view 双 schema，`stateVersion 5 → 6`；宿主全量优先（与其它会话级数字同一 P1 规则），旧宿主退化为空表 → 退回名字胶囊。
- **排序**：soia 包工具排前 → 其余按调用次数降序 → 同数按名字；`失败 > 0` 红字。
- **标签来源**：本仓四个工具用调用方给定的短标签；其他 soia 工具回落 `soia <包描述短语>`；有独立 bundle 行的官方工具标 `基础插件`；`read/write/edit` 这类**没有独立 insert 行**的内置工具不编标签——与插件 ID 卡同口径：没归属就说没有。

## 九、渲染上限与占位行（虚拟占位，2026-09-23，PR #56）

- 档案把整场折进来后行数可达数千：按**轮组**开窗，先渲染最新 `RENDER_STEP = 400` 行当量（表按新→旧绘制，保的是直播尾部——面板存在的意义是"此刻该不该管"），更早的由**底部占位行**`展开更早 N 行`按需补；
- 切割永远发生在**轮组之间**、不切组内（步头与轮上下文不碎）；首组即使超预算也整组渲染；
- **不做滚动数学式真虚拟**：行高可变（两行行、展开明细、生成中行）+ 分组 DOM，精确占位需要逐行测量，复杂度高于收益——占位行 + 增量展开已把 DOM 钉在常数级；
- 单测：`tests/client/render-window.test.ts`（4 例：预算内全显 / 头部保留与隐藏计数 / 超大首组整组 / 空列表）。
