# 「任务」面板：这个界面想表达什么

这份文档回答一个问题：**「任务」页签为什么要长成这样。** 它写给读界面的人，也写给以后改这个界面的人——信息层级先有理由，才有布局。

## 一、面板要支持的判断

读者只有一个问题：**我现在该等，还是该管？**

| 观察 | 结论 |
| --- | --- |
| 有工具在跑、时间在走 | **等**。它在干活。 |
| 很久没有新动作，但回合没结束 | **看**。可能卡住了，去看「最近动静」和「动作日志」。 |
| 出现失败行 | **管**。看失败码和返回首行，决定重试还是改做法。 |
| 「运行状况」显示数据不再更新 | **不信这份面板**。它可能只是没收到数据。 |

前两行是绝大多数使用场景：**扫一眼就走**。因此面板的顺序是「先结论、再证据、最后自检」——而不是把字段按来源罗列。

## 二、模块与它们各自回答的问题

| 顺序 | 模块 | 回答的问题 | 内容 | 空态 |
| --- | --- | --- | --- | --- |
| 0 | 顶部工具行 | **现在用哪个工具** | 在飞工具名（无在飞则最近一次） | `还没有用过工具` |
| 1 | 概览 | **整体什么状况** | 状态 / 位置 / 工具调用数 / 失败数（非 0 标红） | — |
| 2 | 正在跑 | **此刻在做什么** | 工具名 + 参数（命令、路径、`选择器 @ 页面`）+ 已跑秒数 | `现在没有在跑的动作` |
| 3 | 动作日志 | **都干过什么、结果如何** | 五列：时间 · 工具 · 干了什么 · 耗时 · 结果；「全部 N / 只看失败 N」筛选 | `没有符合条件的记录` |
| 4 | 最近动静 | **模型那边有没有动静** | 最多三条人话短句 | 无内容则不渲染该模块 |
| 5 | 运行状况 | **这份面板还可不可信** | 折叠/忽略/未知类型/流式帧/接管 agent/增量接受丢弃/数据新鲜度 | — |

**为什么要"正在跑"和"动作日志"两块而不是一块**：前者是"现在"，后者是"历史"，两者的刷新频率与失败语义不同（在飞调用没有结果，历史行必有结果）。合成一块会让"这一刻在跑什么"淹没在列表里。

**为什么失败要单独可筛**：日志通常只被问一个问题——"有没有出错"。五列里塞一个红徽标不够，因为一旦动作多起来，失败行会被翻页翻掉。

**为什么有"运行状况"**：这块面板的字段全部来自宿主折叠的持久事件。它可能因为上游变化而悄悄停止更新，而"安静"与"坏掉"在屏幕上长得一模一样。把面板自己的数字摆出来，读者才能判断"该不该信这一屏"。

## 三、信息层级的三条规则

1. **先结论后证据**：顶部一行给状态，模块按其重要性排列，明细在最后。
2. **机器词不进门**：`tool/call`、`step/start`、`session-log-*` 这些是会话日志的词汇，不是读者的；面板只出现人话（工具名与事件名是协议标识符，故意保留原样，因为改写会掩盖"到底是哪个工具"）。
3. **数字必须可核**：每一行都能在会话日志里找到出处；面板不做推测，读不出来就报缺失（`—`），不猜。

## 四、刻意不做的事

| 不做 | 理由 |
| --- | --- |
| 流式文本进度条 | 它来自进程内瞬时帧，落不了日志；显示一个恒为 0 的进度条比不显示更糟 |
| 工具返回全文 | 面板是索引不是阅读器；全文在对话记录里 |
| 完整历史 / 审计 | 动作日志是最近 8 次的窗口，不是账本 |
| 写操作（取消、重试） | 只读面板不会误伤；要动手去对话里做 |
| 常驻右侧栏（v1） | 页签已集成并验证；再加一个面板是新的集成面，换来的能力重复 |

## 五、与参考插件的异同

同一套插槽（`conversation.view`）与同一套原语（`StateDot` / `Tag` / `Pill`），因此视觉语言一致。差别在**信息密度**：参考插件（上下文洞察）面向"分析一个会话的构成"，需要图表与树；本面板面向"此刻该不该管"，因此用卡片 + 表格 + 一行结论，宁可留白也不堆数字。
