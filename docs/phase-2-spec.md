## 0. 背景与证据

- 一期 6 包已发布 **v0.1.0**（Release + main `d5d2d34`；dev = `0.1.1-snapshot.0`），512 测试、CI 绿。
- **一期自己留下的边界（这是二期的起点，不是新发明）**：
  - `plugin-plan §一`：插件 2 只覆盖 **DSH 侧**；"Codex / Claude Code 未覆盖"；"跨宿主门禁适配（Claude hooks / Codex approval，三端共用 `danger-patterns.json`）= 未排期（已登记）"；
  - `§五`：MCP 入口当时"等 DSH 侧验证有效后再做"——**验证已做（v0.1.0 六包真跑），调用方本次把它升入二期 = 状态变更，本节记录该裁决**；
  - `§七`：跨宿主的既定形态 = **能力做一份、宿主各配一次**（取数核心单份，DSH 入口 / MCP server 入口各一层薄壳；门禁类"做不成 MCP"，只能每宿主一个适配器，**清单只维护一份**）；
  - `§八` 未决：V3 对拍（需调用方给页面 URL 与选择器）、常驻 token 差分实测（179 是字符估算）；
  - `§更远的候选` 登记池：插件体检 `check-plugins`、`find-skills`、画板对照、额度探针桥、原生拖动取证、worktree 显示。
- 观测到的优化素材（本仓事实）：CI 曾假红（PR #58 首跑 `check-ui-size` 两例 30s 超时，重跑即绿）；面板抽屉无 token 分项、终态/罕见节点未成行；策略 journal 无面；一次不点名试点模型选了 `bash`（N=1，基线未知）。

## 3. 验收（前置 → 动作 → 结果 → 边界）

- **T1.1 MCP**：前置=本机 mcp server 进程；动作：MCP 客户端一行配置后问哈希/门禁/尺寸三类问题各一次；结果：工具经 MCP 调用返回与 DSH 内一致的结构化结果（同一夹具对照 DSH 调用逐字段相等）；边界：客户没配 Chrome → `check_ui_size` 返回既有 typed error，不崩。
- **T1.2/T1.3 门禁适配**：动作：各端各发一条命中危险模式的命令（用 `danger-patterns.json` 的真实样例，如 `Library` 路径 / 宽删）；结果：Claude 端 PreToolUse 返回阻止、Codex 端 approval 呈现拒绝路径；边界：清单文件缺失/不可读 → 默认 fail-closed 并在文档写明（待决④）。
- **T1.4 配置说明**：三端各一段"复制即用"配置 + 一次真实连接成功的日志/截图指针。
- **T2.1**：同 commit 连跑 3 次全绿；根因写进 PR（若为 CI 资源 → 受控重试方案并记录，不掩盖真失败）。
- **T2.2**：产出差分实测表（带插件 vs 不带，同提示词各跑一次），回写预算 note；若实测 > 估算，先报告再决定动预算。
- **T2.3**：V3 项对拍通过（调用方提供 URL/选择器后）。
- **T2.4 入选项**：沿用上一版验收（分项合计=总数；原因码不编造；未知 fail-open；策略计数可标注 journal 开关状态）。
- **T3.1**：构造"装了未加载"与"加载未调用"两态，工具分别返回对应状态 + 证据指针；真会话答一次"现在六包加载状态"。
- **T3.2**：给定任务措辞返回排序候选（名称+理由）；不点名提示下模型选中正确技能的命中率先测后定（待决③）；未过阈值 → 工具不启用（保持登记状态）。
- **T3.3**：与 T2.3 同批验收（依赖满足才开工）。

## 5. 依赖、风险、假设、待决

**依赖**：调用方提供 V3 页面 URL/选择器（T2.3）；Claude/Codex 两端 hook/approval 的官方机制文档（T1.2/1.3 首跑以官方文档为准）；MCP 客户端测试环境（Claude/Codex/其它各一）。

**风险**：
1. MCP 只扩展"可用"，**不提供拦截**——文档必须写清（§七边界），避免误以为装了 MCP 就有门禁；
2. 清单单源但三端执行语义不同（DSH guard vs hook vs approval），**三端各跑真实样例**，不拿一端绿代表三端；
3. find-skills 的常驻 token 是真实代价（≈120–160），不达数据条件就不上；
4. 新包（T3.1/T3.2）受 npm 不做约束 → git 源分发，但仍要过 CONTRIBUTING §1 全套清单（README 三件套、i18n、预算、门禁）。

**假设**：二期 = 六包 + 至多两个新包，不引入治理/角色/成本类（§五理由未变）。

**待决（评审拍板）**：
1. **T1.1 MCP 首发工具集**：四工具全上（建议）还是先 1–2 个？
2. **T2.4 面板子项勾选**：F2 分项 / F3 终态 / F4 节点 / F5 策略 / F7 跟随——勾哪几条？
3. **T3.2 数据开关**：用什么指标与阈值判定"值得花 120–160 token"（建议：S6 前先出 `check_skills` 命中数据，阈值到时定）？
4. **门禁缺清单时默认**：fail-closed（建议，与 DSH 侧一致）还是 fail-open？
5. **切片顺序**：默认 S1→S3（稳定性与门禁先行）；要先看到"其他 AI 能用"就 S2 先行。
