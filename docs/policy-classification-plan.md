# 工具调用分类：方案与状态

适用范围：`packages/safe-tool-call-policy`。本文记录**判断一个工具调用该不该被拦**这件事的分层设计、
当前实现状态，以及尚未决定的事项。裁决与验证结果登记在 [verification.md](verification.md)。

## 为什么要分类，而不只是匹配

现有规则是**文本匹配器**：命中一段模式就给一个动作。它能覆盖已知形状，但回答不了两个决定"要不要人来
看一眼"的问题——**这是什么性质的改动**、**影响范围多大**——也没有置信度，因此无法用真实流量校准。

实测代价（2026-09-22，25,556 条去重命令回放）：修掉噪声前命中率 10.2%，其中 81% 是只读诊断命令被
拦下；在审批关闭的会话里，`ask` 等于静默拒绝，操作者看到的是"用户拒绝"，而他什么都没看到。

## 三层结构

| 层 | 做什么 | 依赖 | 默认 |
| --- | --- | --- | --- |
| **L0 确定性规则** | `danger-patterns.json` + 只读快通道 + 命令投影；`deny` 的地板 | 无 | **开启**，所有人 |
| **L1 结构分类** | 把命令解析成 `action`/`target`/`blastRadius`/`reversible`/`credentialAccess` + `confidence` + `evidence` | 无（纯本地） | 可选，`observe` 观察 |
| **L2 类型化判断模型** | 用 `choice`/`score`/`noul` 式的分类器做第二信号 | 外部 API | **未引入**，保留接缝 |

### L0：不变量

- `deny`（数据根写入、系统路径、凭证外泄）**不交给模型判断**，永远是地板。
- 只读命令只跑 `deny` 规则；不允许询问的会话里，`ask` 降级为"只记录不拦"。
- 命令投影：`echo` 参数与"写入文件"的 heredoc 正文不参与匹配。

### L1：离线分类（可选，草稿在 `src/shared/classify.ts`）

纯本地、每次调用可跑。输出是类型化判断而不是布尔值，因此可以：

- 用**同一个判据**给出"删除临时目录"与"删除数据根"的差别（`target` + `blastRadius` + `reversible`）；
- 先以 `observe` 模式记录判定与置信度，用回放语料**离线校准**阈值，再决定是否参与拦截；
- 在遥测里区分"规则命中"与"分类器认为有风险"，避免两者混成一个数字。

当前状态：代码与 16 条用例**已随 #36 进入 dev**（`src/shared/classify.ts`，未接入运行时，没有任何调用方）；**去留仍待 Owner 决定**——移除只是删两个文件，不影响任何行为。

### L2：类型化判断模型（未引入）

生态里的做法（如把类型化判断模型当**第二信号**用于风险门控）是：只发命令文本、**先记录后阻断**、
阈值按动作风险分档并且用自己的样本调；同时明确它**不是安全边界**。

若将来引入，接缝应满足：

- 默认关闭；`SOIA_POLICY_JUDGMENT=off|observe|enforce`，只有显式配置才联网。
- 只发**脱敏后的命令文本**，不发文件内容、不发工具结果；脱敏逻辑见 `src/host/decisions.ts` 的 `redact()`。
- 硬超时（建议 ≤800ms）、失败回退到 L0/L1（不阻塞工作）、相同命令的判定本地缓存、每会话预算上限。
- `deny` 仍由 L0 决定，模型只在 `allow/ask` 区间给出意见。

## 待定事项

1. **是否允许命令文本离开本机**（L2 的前置条件）。
2. L1 是否保留、以什么模式上线（`observe` 还是参与拦截）。
3. L2 供应商与凭据存放位置（本仓只报位置与形态，不读值）。

## 与插件面板的关系

面板的「运行状况」应能回答"判定来自哪一层、准不准"：规则命中数、分类器判定分布、只观察未拦截的次数。
在没有 L1/L2 的今天，面板只报 L0 的命中与折叠计数。
